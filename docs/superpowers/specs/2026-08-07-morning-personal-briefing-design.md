# 朝のパーソナル通知「今日のきみの1日」 設計

作成日: 2026-08-07

## 背景・目的

家族（小学校高学年〜中高生の子ども3人）はアカウント・端末を持っているが、アプリを開く習慣・動機がない。子どもたちの利用促進のため、A→B→C の段階導入を計画し、本仕様はその第1弾（案A）。

- 案A（本仕様）: 朝のパーソナル通知 — 「毎朝開く理由」を作る（実用・通知型）
- 案B（次段階）: タスク完了・予定へのリアクション（コミュニケーション型）
- 案C（将来）: ポイント＆ごほうび（実利型）

**成功の定義**: 子どもたちが毎朝通知をタップしてアプリを開き、自分の予定・タスク・家族の予定を把握する習慣がつくこと。

## 概要

毎朝、設定時刻に各ユーザーへ**その人専用の内容**のプッシュ通知を送る。タップすると自分専用ビュー `/calendar/my`（既存）が開く。

現在のカレンダーリマインダーは全員一律の固定文（「今日の予定を確認しましょう」）を送っている。これを**パーソナライズされた内容に置き換える**。新しい通知種別は追加しない。

### 方針: 既存カレンダー通知の「中身を良くする」

| 判断 | 内容 |
|---|---|
| 採用 | 既存 `FamilyCalendarNotificationService` の通知内容をパーソナライズ |
| 不採用 | 新通知種別「今日のきみの1日」を別設定として追加（設定UIが煩雑になるだけ。既存の固定文通知に残す価値がない） |

この方針により **スキーマ変更・マイグレーション・cron 変更は一切不要**。

## 通知内容

### フォーマット

- タイトル: `🌞 {display_name}さんの今日`
- 本文: `予定: 16:00 塾 ほか1件 ／ タスク3件 ／ 晩ごはん: カレーライス`
- URL（タップ時の遷移先）: `/calendar/my`

### 組み立てルール

| 要素 | 内容 | データソース |
|---|---|---|
| 予定 | 本人の予定＋参加予定を時刻順に先頭1件表示、残りは「ほか n 件」 | `Plan`（本人所有）＋ `PlanParticipant` 経由の参加予定、当日分 |
| タスク | 当日の未完了タスク数（`タスク3件`）。0件なら省略 | `Task.for_user(user).for_date(today).pending` |
| 晩ごはん | 家族の当日夕食（meal_type=2: 夕）に紐づく food 名。複数品は先頭1品＋「など」。未登録なら省略 | `Meal.for_family(...).for_date(today)` + `foods` |

### 空の日の扱い

習慣化が目的のため、**内容が空でも通知は必ず送る**。

| 状態 | 本文例 |
|---|---|
| 予定なし・タスクあり | `今日は予定なし！ ／ タスク2件 ／ 晩ごはん: カレーライス` |
| 全要素なし | `今日はフリーだよ。カレンダーをのぞいてみよう` |

### 文字数制限

プッシュ通知の本文は表示環境により切り詰められるため、全体を**おおむね 60 文字以内**に収める（予定タイトルは長い場合 10 文字程度で省略記号付き切り詰め）。

## 実装

### 変更ファイル

| ファイル | 変更 |
|---|---|
| `app/services/family_calendar_notification_service.rb` | 通知内容の組み立てロジックを実装（本仕様の中核） |
| `app/views/settings/*`（該当箇所） | 設定画面の「カレンダーリマインダー」の説明文を新しい内容に合わせて更新 |

### 変更しないもの

- `POST /api/scheduled_notifications/trigger`（cron からの起動、対象者抽出）
- `UserNotificationSetting`（設定スキーマ・バリデーション）
- `PushNotificationService`（`url:` パラメータで deep link 対応済み）

### FamilyCalendarNotificationService の構成

```
notify(user)
  ├─ build_title(user)         … 🌞 {name}さんの今日
  ├─ build_message(user, today)
  │    ├─ plans_segment        … 本人＋参加予定（時刻順）
  │    ├─ tasks_segment        … 未完了タスク数
  │    └─ dinner_segment       … 家族の夕食
  └─ PushNotificationService.send_to_user(..., url: my_calendar URL)
```

- `today` は `Date.current`（アプリのタイムゾーン）を基準とする。
- 各 segment が nil を返したら本文から除外し、`／` で結合する。

## エラー処理

- プッシュ送信失敗は既存 `PushNotificationService` の rescue + ログで吸収（変更なし）。
- 内容組み立て中の予期しない例外で trigger 全体（他ユーザーへの送信）が止まらないよう、`Api::ScheduledNotificationsController#trigger` の `find_each` ループ内で 1 ユーザー単位で例外を rescue してログに残す（現状この保護は無いため追加する）。

## テスト

`spec/services/family_calendar_notification_service_spec.rb` で内容組み立てを網羅する。

- 予定あり/なし × タスクあり/なし × 晩ごはんあり/なし の組み合わせ
- 参加予定（PlanParticipant 経由）が予定に含まれること
- 予定が複数件あるとき「ほか n 件」表示になること
- 夕食に複数品目があるとき「〜など」表示になること
- 全要素なしでもフォールバック文で送信されること
- `url` に `/calendar/my` が渡ること

RAILS_ENV=test を明示して実行する（dev コンテナは development がデフォルトのため）。

## ロールアウト

コード外の作業は、子どもたち各自の設定画面で「カレンダーリマインダー」を朝の時刻（例: 7 時）で有効にするだけ。

## スコープ外（次段階）

- 案B: タスク完了・予定へのリアクション（👏🎉 等）と双方向通知ループ
- 案C: ポイント＆ごほうび制度
- 通知内容のユーザー別カスタマイズ（含める要素の選択など）
