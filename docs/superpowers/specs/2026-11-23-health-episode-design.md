# 簡易医療記録（体調エピソード）設計

作成日: 2026-11-23
関連タスク: Inkdrop `cast-me`「簡易医療記録（体温など）をつけられるようにする」

## 前提

- PR #112（分単位で動くリマインダ送信基盤）がマージ済みであること。
  未マージの間は通知以外を先に実装し、通知は #112 の後に回す。

## 背景・目的

病気のときに体温・症状・服薬を残す場所がない。家族の誰かの看病記録を、
「病気のまとまり（体調エピソード）」単位で残せるようにする。

体温は測ったときに記録し、服薬だけを時刻でリマインドする。

## ゴール

- 体調エピソードを作れる（対象者・病名・開始日・終了日・状態）
- エピソードに体温（測定時刻 + 値）を何度でも記録できる
- エピソードに症状を1つの自由記述で残せる
- 服薬は家族共通のマスタ（名前のみ）から選び、エピソードごとに通知時刻を決められる
- 通知時刻に服薬リマインドを push する（宛先は対象者本人）
- 週間表示と「月のできごと」にエピソードが出る
- 「直った」で終了、「解除」で進行中に戻せる

## 非ゴール

- カレンダー（月グリッド）へのエピソード表示（予定・タスクで既に混むため出さない）
- 服薬の実施記録（飲んだかどうかは追わない）
- 体温測定のリマインド
- 症状の日別記録（エピソードに1つ）

## データモデル（案）

Ridgepole（`db/Schemafile`）で管理。SQLite のためカラムは追加のみ。

### `health_episodes`

| カラム | 型 | 備考 |
|---|---|---|
| family_id | bigint | 必須 |
| user_id | bigint | 対象者（家族の誰か）。代理入力可 |
| title | string | 病名・症状名（「インフルエンザ」「発熱」など自由記述）。必須 |
| started_on | date | 必須。既定は今日 |
| ended_on | date | 「直った」を押した日。進行中は NULL |
| status | integer | 0: active, 1: recovered |
| symptom_note | text | 症状・経過の自由記述（1つ） |

インデックス: `[family_id, started_on]`, `[user_id, started_on]`, `[status]`

### `health_episode_temperatures`

| カラム | 型 | 備考 |
|---|---|---|
| health_episode_id | bigint | 必須 |
| measured_at | datetime | 測定時刻。既定は現在時刻 |
| value | decimal(3,1) | 例: 36.5 / 39.2 |

インデックス: `[health_episode_id, measured_at]`

### `medications`（家族共通マスタ）

| カラム | 型 | 備考 |
|---|---|---|
| family_id | bigint | 必須 |
| name | string | 薬名のみ |

インデックス: `[family_id, name]`（UNIQUE）

マスタは追加・改名のみで、削除機能は持たない（過去のエピソードからの参照を壊さない）。

### `health_episode_medications`

| カラム | 型 |
|---|---|
| health_episode_id | bigint |
| medication_id | bigint |

インデックス: `[health_episode_id, medication_id]`（UNIQUE）

### `health_episode_reminder_times`

| カラム | 型 | 備考 |
|---|---|---|
| health_episode_id | bigint | 必須 |
| hour | integer | 0..23 |
| minute | integer | 0 か 30（既存の通知設定と同じ30分刻み） |

インデックス: `[health_episode_id, hour, minute]`（UNIQUE）

## 状態遷移

```
active --「直った」--> recovered（ended_on = 今日）
recovered --「解除」--> active（ended_on = NULL に戻す）
```

記録（体温・症状・服薬）は状態にかかわらず残す。誤操作で消えない。

## 画面

### 入口

カレンダーの日付ヘッダー（「11月23日」の横）にあるボタン群を「その他」メニューにまとめ、
そこに「体調記録」を追加する。

- 既存の「予定追加」「タスク追加」「まとめて追加」も同じメニューに入れる
- 「体調記録」を選ぶと、その日を開始日の初期値にして新規エピソードのフォームを開く

### エピソード詳細

- 対象者・病名・期間・状態
- 体温リスト: 日ごとにグループ化（時刻 + 値）。追加フォームは現在時刻・空欄の値から
- 症状メモ（textarea）
- 服薬: 家族マスタから選択（複数）。マスタに無い薬はその場で追加
- 通知時刻: 30分刻みで複数設定
- 「直った」ボタン（進行中のみ）／「解除」ボタン（回復済みのみ）

### 編集

- 作成時に終了日も指定できる（過去の病気を後から登録するため）。終了日が入っていれば recovered。
- 対象者・病名・開始日・終了日は作成後も編集できる。
- 体温は追加・修正・削除できる。状態にかかわらず記録は残す。
- `status` と `ended_on` は同時に更新する（`ended_on` があれば recovered）。

### 週間表示

メンバー行とは別に「体調」の行を設け、エピソードのあるメンバーだけ1行ずつ表示する。
7日分をまたぐ帯を描き、帯には病名を出す。タップでエピソード詳細へ。
日ごとのセルの中には繰り返さない（同じ帯が7回並ぶのを避ける）。

### 月のできごと（旧: 月間予定リスト）

サイドパネルの一覧に予定とエピソードを日付順で並べる。
エピソードは開始日に表示し、期間（開始〜終了）を併記する。

名称変更:

- パネルの見出し「◯月の予定一覧」→「◯月のできごと」
- ボタンの title「月間予定リスト」→「月のできごと」

## 通知

既存の `ReminderDispatcher`（1分ごと・30分スロット・`NotificationDispatch` の UNIQUE で排他）に
体調エピソード用の種別を追加する。

- 対象: `status = active` かつ `started_on <= 今日` のエピソードの通知時刻に一致する枠
- 宛先: エピソードの対象者（OneSignal の external_id）
- 文面: 「服薬の時間です」＋ 病名。薬名が分かる場合は列挙する
- 重複防止: 既存と同じく `NotificationDispatch` で枠を排他する
- エピソードが終了（recovered）したら送らない
- 同じ対象者・同じ時刻に複数のエピソードが重なる場合は1通にまとめ、病名を併記する
  （排他キーは既存の `kind:user_id:slot` のまま）

### 割り切り

- 対象者が端末を持っていない場合（子どもなど）は通知が届かない。
  代理入力はできるが、通知の宛先は対象者本人のみとする
- 通知時刻はエピソードごとに持ち、服薬ごとの時刻指定はしない

## 既存機能との関係

- 家族・ユーザーのスコープは既存と同じ（`family_id` / `user_id`）
- 体温は日付ベースの既存記録（食事・タスク・予定）と並ぶが、独立した画面で扱う
- 通知は既存の仕組みを再利用し、新しい常駐プロセスは増やさない

## 実装者に委ねる判断

- 通知文面の細部（薬名をどこまで出すか）
- エピソードの一覧画面を持つか（週間表示・月のできごと・詳細だけでも成立する）
- 体温の入力 UI（数値入力の刻み、37.5 などのプリセット）
- エピソードの削除を許すか（「解除」で戻せるので、削除は不要かもしれない）
- テーブル名・モデル名の最終決定（ここでは `health_episode_*` の仮名）

## 制約

- 本番は 1GB の Lightsail 1台、常駐プロセスなし。通知は既存 dispatcher 内で処理する
- タイムゾーンは `Asia/Tokyo` 固定
- スキーマは Ridgepole。SQLite のためリネームは行わず追加のみ
